# 色立体 (Color Solid Viewer)

**PCCS**・**マンセル**・**HSV**・**CIELAB** の4つの色分類（表色系・色空間）の色立体を、ブラウザ上で3D表示するWebアプリです。色相・明度・彩度の3属性で色を立体配置し、マウスで回転・ズームしながら観察できます。各色チップをクリックすると、その分類の表記（例 マンセル `5R 4/14` / PCCS `2:R 4.0-9.0s` / HSV `H210 S80 V90` / CIELAB `L*60 C*40 h210`）とsRGB値を確認できます。ヘッダーの「表色系」でいつでも切り替えられます（初期表示は PCCS）。

デザイン・教育・色彩検定の学習など、「色空間が実際にどんな形をしているか」を直感的につかみたい人向けです。同じ色でも分類ごとに立体の形（円柱／非対称な木）が違うのを見比べられます。

## 色立体と各分類の解説

### 色立体とは
色は「色相（赤・黄・青などの系統）」「明度（明るさ）」「彩度（鮮やかさ）」の3つの属性で表せます。この3属性を3次元空間に配置したものが**色立体**です。本アプリでは次のように対応づけています。

- 色相 → 垂直軸まわりの角度（円周）
- 明度 → 垂直方向の高さ（下が暗い、上が明るい）
- 彩度 → 中心軸からの距離（中心が無彩色＝グレー、外へ行くほど鮮やか）

無彩色（白〜グレー〜黒）は中心の縦軸に並びます。立体がきれいな円柱でなく「でこぼこした木」のように非対称なのは、鮮やかにできる度合い（最大彩度）が色相や明度ごとに違うためです。

### マンセル表色系 (Munsell)
アメリカの美術教師 A. H. マンセルが考案し、のちに測色的に整備された表色系です。知覚的な等歩度（見た目の差が各ステップでそろうこと）を重視しています。

- **色相 (Hue)**: R, YR, Y, GY, G, BG, B, PB, P, RP の10色相を基本とし、各色相を10分割した100段階の色相環。各色相の中心が `5`（例 `5R`）。
- **明度 (Value)**: 0（黒）〜10（白）。
- **彩度 (Chroma)**: 無彩色の0から始まり、上限は色相・明度によって異なる（鮮やかな赤などは14以上まで伸びる）。
- **表記**: `色相 明度/彩度`。例 `5R 4/14`（やや暗く非常に鮮やかな赤）。無彩色は `N` 記法（例 `N 5/`）。

特徴は、彩度の上限が一定でないため色立体が非対称になること。色の厳密な指定・管理（塗料、土壌、品質基準など）に広く使われます。

### PCCS (日本色研配色体系)
日本色彩研究所が**配色**のために開発した表色系です。色相と彩度・明度を扱いつつ、「**トーン（色調）**」という概念で明度と彩度をまとめて捉えられるのが最大の特徴で、配色やデザイン教育で重宝されます。

- **色相 (Hue)**: 24色相を等間隔に配置（1:pR 〜 24:RP）。心理4原色（赤・黄・緑・青）を基準に等間隔化されています。
- **明度 (Lightness)**: およそ 1.0〜9.5。
- **彩度 (Saturation)**: 1s〜9s の9段階（`s` は saturation）。
- **トーン**: 明度と彩度の組み合わせを `v(ビビッド)`, `b(ブライト)`, `s(ストロング)`, `dp(ディープ)`, `lt(ライト)`, `sf(ソフト)`, `d(ダル)`, `dk(ダーク)`, `p(ペール)`, `ltg(ライトグレイッシュ)`, `g(グレイッシュ)`, `dkg(ダークグレイッシュ)` の12トーンに整理。「同じトーンで色相だけ変える」といった配色がしやすい。
- **表記**: 本アプリでは `色相 明度-彩度s`。例 `2:R 4.0-9.0s`。無彩色は `n` 記法（例 `n5`）。

### HSV
コンピューターで広く使われる色の表し方です。sRGB と**正確に**相互変換できます。

- **色相 (H)**: 0〜360°（0=赤, 120=緑, 240=青）。
- **彩度 (S)**: 0〜100%。
- **明度 (V)**: 0〜100%。
- **表記**: 本アプリでは `H.. S.. V..`（例 `H210 S80 V90`）。
- 色立体はきれいな**円柱**になります。Webやデザインツールの色指定に向いています。

### CIELAB (LCh表示)
CIE が定めた**知覚的に均等**な色空間で、色差(ΔE)の計算などに使われます。本アプリでは円柱形の LCh（明度 L*・彩度 C*・色相 h）で表示します。

- **明度 (L*)**: 0（黒）〜100（白）。
- **彩度 (C*)**: 0から。鮮やかなほど大きい。
- **色相 (h)**: 0〜360°。
- **表記**: `L*.. C*.. h..`（例 `L*60 C*40 h210`）。
- Lab→sRGB は**厳密**。表示される立体は sRGB で出せる色の形（非対称）です。

### 違いと使い分け
| | マンセル | PCCS | HSV | CIELAB |
|---|---|---|---|---|
| 主目的 | 色の正確な記述・管理 | 配色・デザイン教育 | 画面・ツールでの色指定 | 色差計算・測色 |
| 色相 | 100段階（基本10色相） | 24色相（等間隔） | 0〜360° | 0〜360° |
| 明度 | 0〜10 | 約1〜9.5 | V 0〜100 | L* 0〜100 |
| 彩度 | 色相/明度で上限が変動 | 1s〜9s | S 0〜100 | C* 0〜約130 |
| sRGB変換 | 近似(CIELAB経由) | 近似(CIELAB経由) | **厳密** | **厳密** |
| 立体の形 | 非対称 | 非対称 | 円柱 | 非対称(sRGB域) |

ざっくり言うと、**正確に伝えるならマンセル、配色なら PCCS、画面の色指定なら HSV、色差や測色なら CIELAB** が向いています。4つを切り替えると、同じ色でも色相の刻みや立体の形が違って見えるのが分かります。

> 注: マンセルと PCCS の色は CIELAB を経由した**近似**です（HSV・CIELAB は厳密）。いずれも学習・観察が目的で、マンセル/PCCS は厳密な測色値とは一致しません。

## 主な機能
- PCCS / マンセル / HSV / CIELAB の色立体を3Dで描画（色相=円周, 明度=高さ, 彩度=中心からの距離）
- ヘッダーの「表色系」セレクトで4つの色立体を切り替え（初期表示は PCCS）
- マウスでグリグリ回転・ズーム・パン（OrbitControls）
- 各色チップは各表色系→sRGB変換に基づいた色で表示
- 色チップをクリックすると表色系の表記と sRGB / HEX を表示
- 明度・彩度のスライス表示（明度/彩度ごとのボタンで複数選択でき、両方を同時に効かせて断面や特定の彩度リングを抜き出せる）。彩度ボタンは立体に実在する彩度だけを表示
- sRGB色域外（表現できない色）を含めるか除外するかの切り替え
- 配色パターン生成（補色・類似色・トライアド・テトラード・モノクロマティック・シェード・ティント）。結果の色は色立体上に枠線で示し、クリックで該当チップへフォーカス

## 技術スタック
- 言語/実行環境: HTML + JavaScript (ES Modules)、ビルド不要の静的構成
- 主要ライブラリ: [Three.js](https://threejs.org/)（3D描画・OrbitControls）
- 色変換: マンセル / PCCS とも CIELAB を経由して sRGB へ変換（近似）。表色系ごとに共通インターフェース（system descriptor）で実装
- データ保存: なし（色データはブラウザ内で生成）
- 外部ツール: 不要（XAMPP も不要。静的ファイルだけで動作）

## ローカルで動かす（開発者向け）
ビルドは不要です。ただし ES Modules を使うため `file://` で直接開くと CORS 制約で動きません。簡易サーバー経由で開いてください。

```bash
# 取得
git clone https://github.com/toreno/color3d.git
cd color3d

# いずれかの方法でサーバーを立てて開く
python -m http.server 8000      # → http://127.0.0.1:8000/
# または
npx serve .
# または XAMPP の htdocs 配下なら http://localhost/color3d/
```

## 使い方
1. ページを開くと中央に色立体が表示されます（初期はマンセル）。
2. ドラッグで回転、ホイールでズーム、右ドラッグ（または2本指）でパン。
3. 色チップをクリックすると、右側のパネルに色の表記・sRGB・HEX が表示されます。
4. 明度・彩度のスライスボタンで、特定の明度/彩度だけを抜き出して観察できます（複数選択・併用可）。
5. 「色域外を含む」トグルで、sRGBで表現できない色の扱いを切り替えられます。
6. ヘッダーの「表色系」で マンセル / PCCS を切り替えられます。
7. 「配色パターン」でベースカラーから配色を生成し、色立体上の位置を確認できます。

## ディレクトリ構成
```
.
├─ index.html          # エントリ（画面・UI）
├─ css/
│   └─ style.css       # スタイル
├─ js/
│   ├─ main.js         # シーン構築・UI・インタラクション・表色系切り替え
│   ├─ munsell.js      # マンセル変換 + 配色 + system descriptor
│   ├─ pccs.js         # PCCS 変換 + 配色 + system descriptor
│   ├─ hsv.js          # HSV 変換（厳密）+ 配色 + system descriptor
│   ├─ cielab.js       # CIELAB(LCh) 変換（厳密）+ 配色 + system descriptor
│   └─ solid.js        # 色立体メッシュの生成（表色系非依存）
└─ README.md
```

各表色系は共通インターフェース（`system descriptor`: `toSRGB` / `fromSRGB` / `format` / `generateScheme` / 軸レンジなど）を実装し、`solid.js` と `main.js` はそれ経由で動くため、新しい表色系の追加も descriptor を1つ作るだけで済みます。

## 色変換について（データの扱い）
- マンセルは「色相 / 明度 / 彩度」（例 `5R 4/14`）、PCCS は「色相(1〜24) / 明度 / 彩度」（例 `2:R 4.0-9.0s`）で表します。
- どちらも CIELAB を経由して sRGB へ変換します（Hue→Lab色相角, Value/明度→L*, Chroma/彩度→Lab C*、その後 Lab→sRGB）。
- 色立体の形が円柱ではなく「でこぼこした木」のように非対称なのは、sRGBで表現できる範囲が色相・明度ごとに異なるためで、仕様どおりの挙動です。
- 変換は近似を含みます（特に PCCS は方針Aの簡易モデル）。厳密な測色用途ではなく、形状と色味の理解を目的としています。

## GitHub Pages で公開する
このアプリは静的ファイルだけなので、GitHub Pages にそのまま載せられます（ビルド設定不要）。

このリポジトリは初期化・初回コミット・リモート登録（`https://github.com/toreno/color3d.git`）まで済んでいます。残りの手順は次のとおりです。

1. GitHub で空のリポジトリ `color3d` を作成する（README/LICENSE は追加しない）。
2. ローカルから push する。

   ```bash
   git push -u origin main
   ```

3. リポジトリの **Settings → Pages** を開く。
4. **Build and deployment** の Source を **Deploy from a branch** にし、Branch を **main / (root)** に設定して保存。
5. 1〜2分待つと `https://toreno.github.io/color3d/` が発行される。

補足:
- `index.html` がリポジトリ直下にあるので、追加設定なしでトップページになります。
- Three.js は CDN（unpkg、バージョン固定）から読み込むため、同梱は不要です。CDN に依存したくない場合は `js/vendor/` に置いて import map を書き換えてください。
- 独自ドメインを使う場合は Pages の Custom domain を設定します。

## トラブルシュート
- 画面が真っ白 / モジュールエラー → ローカルでは `file://` ではなく簡易サーバー経由で開く（「ローカルで動かす」参照）。公開版では通常発生しません。
- 3Dが表示されない → ブラウザのWebGL有効化を確認。コンソールのエラーを確認。
- 色が全体的におかしい → `js/munsell.js` / `js/pccs.js` の変換・ガンマ補正まわりを確認。
- Pages で404 → Pages の Source 設定（main / root）とデプロイ完了を確認。パスは末尾スラッシュ付き（`.../color3d/`）で開く。
